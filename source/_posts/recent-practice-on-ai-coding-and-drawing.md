## ai 的能力

现在说的 ai 大多是指 llm (大语言模型, large language model).
llm 其实是**精准的信息整理**. 
我们认为 "ai 可以整理文件夹, 写ppt, 逆向工程, 开发软件", 只是被 llm 被装上了"手脚", 这些"手脚"并不是 ai, 是早就有了的.

很多 ai 相关新闻是被夸大的, 很多东西是没 llm 的时候就有的, 当然, 这种"新闻的夸大"也是没 ai 前就有的.

### 工具和生态

ai 新闻是傻逼的, 但 ai 的"手脚"是有实际意义的. 他们好比给人类的大脑装上身体, 好比太乙真人给哪吒的魂魄装上荷花化身.

llm 的输出只有字符串, **我们感受上的"帮我写代码, 帮我下载安装, 帮我整理文件, 帮我格式化电脑", 都是通过你跟 ai 说话的那个 agent(代理程序)调用了不同工具进行操作的.
而 tool, mcp, cli 其实是一个角色, 就是"手脚".** (其实也有"眼睛耳朵")

然后 agent 是负责把整个流程串起来的东西, 可能像是从大脑传出去的神经系统.
他除了协调 llm 和 tool 之间的协议外, 聊天历史(llm 是无状态的), 规范约定也都是 agent 做的.

llm 能让人感觉那么厉害, 是因为他的准确度非常高. 再加上 agent 和 tool 的配合, 所以给普通人提供了很大的帮助:

+ 节省搜索资料, 一个个搜索结果打开过滤信息的时间.
+ 解放查看文档的时间, 以前用个复杂的包需要花好久才能写个简单 demo.
+ 节省操作时间. **对于原先没有动手能力的人特别友好**. 比如下载, 执行命令, 安装报错, 本来不同程度的麻烦可以拦掉不同熟悉程度的人让人放弃下一步.
+ 节省文本分析时间. 一部分人的工作是有文本分析提取一些信息的重复工作, 不能简单通过正则提取, 如果能用上会节省很多精力.
+ 节省编码时间. 原先我们说的"体力活"代码都可以不写了.

### ai 有没有创造能力

基于 llm 的训练方式, 模型产出都是基于训练数据的, **是不会造新东西的**.

我在训练角色 lora 的时候意识到, 只有角色正面的训练数据训练的模型, 是不能产出角色侧面图片的.

但这样就可以说 "ai 没有创造能力"吗? 很难说, 这涉及"什么是创造"的问题, 创造可能就是组合.
人类的创造也是基于现实世界的, 而且"不基于现实世界的创造"是无法被别人认可, 也无法被认为是"创造"的.

但可以确定的是, 人类的创造的上限更高, 这是底层结构决定的, 在研发出新的训练架构前人类的创造能力是高于 ai 的.
当然现在 ai 可以认为是"创造质检员", 来判断一个东西是真创造还是简单的整理与组合.

## ai 的能力边界

知道 ai 能做什么与不能做什么, 都是需要思考的, 并且有价值的.
**知道 ai 能做什么可以扩展自己的能力, 知道 ai 不能做什么可以知道自己做什么是有意义, 不徒劳的.**

### 犯错

与刚才讨论的"创造力"一样, 是人就会犯错, 所以犯错并不是 ai 特有的问题.
而 ai 犯的错是需要人负责的, 这有点像员工犯错领导是要负责的一样.
所以解决方案也是以前就有的: 解耦, 测试用例, 异常检测, 回滚方案.

### 修改方案

众所周知代码是第一个被 llm 攻占的领域, 原因除了"语言"是被"大语言模型"最佳适配外, **还有一点是 ai 生成的代码可以随意改**这一个天生特质.
再加代码生态里的版本控制和 diff 展示都是百年前就成熟的系统了, 自然第一个打击编码了.

而 ai 出图和视频叫"抽卡", 开始只能通过提示词工程提高抽卡概率, 出图和出视频的成本又比代码高得多.
大家在解决图片视频掌控性方面, 除了提示词, 还尝试了很多办法:
+ inpaint 模型配合 alpha通道实现局部抽卡
+ ControlNet 实现结构控制
+ 工作流生产图层和表达式
+ 模拟操作软件替代 diffusion 模型
其中1和2在一些专用 agent 里也会有"画骨架"或者"勾选区域"等 gui 上的设计.
controlnet能产出一些"ai特有"的图片, 比如像蔡徐坤一样的鸡, 看似风景的二维码, 2个女高远看是牛逼二字之类的图片.(这和小节主题无关)

无论是什么领域, aigc 可以越大程度上被操作, 那么在这个领域 ai 用得就更顺手, 更省力.

### 上下文限制与场景限制

上下文限制可能是编码特有的问题, 真正用 ai 写代码会发现, 项目越复杂, 改动涉及项目里其他内容越多, 模型降智就越厉害.
ai 编程遇到最麻烦的情况就是 ai 反复验证重试一个问题, 导致 token 和时间大量消耗而没有实际紧张, 只能人工深度介入.

有过真实工作经验的朋友知道真实项目可不是广告里那样从零开始弄一个 demo 这么简单.
不光项目很大需要压缩上下文, 还可能改动还涉及对其他系统的影响.

另外一个情况是如游戏外挂, 游戏开发的场景, 暂时还没有 tool 反馈给 ai, ai 就等于是瞎子写代码, 是寸步难行的.

因为上面这2个原因, **正经项目脱离人是很难的, 一定需要人的维护**.
而我们的精力也应该从 api 调用转移到代码结构上.
通过确定代码结构, 充分解耦, 完善测试用例来提高系统的可维护性.

### 了解ai能力

除了 ai 限制, 人还要知道 ai 能做什么, 可以**尽可能利用工具增强个人能力**, 比如开发软件, 比如逆向工程. 
其实这个问题也不是 ai 时代才有的, 大家用的手机软件其实也开发率很低的.

我作为前软件开发者, 本来就会自己弄一些顺手轻便的软件. 我非常清楚的知道, 这些小软件已经是普通人一句话就能搞定的了.
工作会使用电子设备进行某些程度的重复操作的, 都可以让 ai 帮忙写脚本或软件, 节省大量时间. 部分积极的人知道让 ai 干活, 但是不知道一些机械工作可以直接写脚本定时跑来节省 token.
玩游戏的时候也可以让 ai 写辅助软件代肝.
但并**不是所有人都能意识到他们可以这样做**. 就像老阿姨在肯德基买20块一个汉堡一样, 他们不知道自己可以10块买.

举个我个人的例子, comfyui 官方最近公测了 agent, 没有免费版, 最低档是20刀, agent 对话可以生成工作流, 但需要付费才能跑.
但在 comfyui 官方 agent 出现前, 我早用免费的桌面 agent 来控制 comfyui 了.
让桌面 agent 安装 comfyui 和相关依赖, 下载十来个常用模型, 提前写好几个常用工作流, 用不到 agent 每天免费签到积分的 5分之1.
不光可以聊天改提示词, 改工作流, 还可以让 agent 写训练 lora 的脚本, 自动程度相当高, 都是免费的.

在做这些事之前, 我记得还在用 ai 写 ae 脚本, 现在看来那是徒劳.
有了逆向工程的新闻后, 我又有一瞬觉得是不是现在在弄的软件也是徒劳.
才觉得应该打开眼睛, 边对正在做的事情深入, 也边要探索更多的实践, 以避免花很多精力做无用功和自我感动.

## 模型之间的关系

ai 的图谱非常大, 大语言模型(llm)和作图模型(diffusion model)的共同祖先是神经网络, 所以从神经网络开始理一下, 了解下现在发展迅速领域的一些概念.

### 神经网络

神经网络算是种仿生技术, 人体神经细胞是各个轴突受到了一定的电信号达到阈值就把电信号传到下个神经细胞.
电子神经元就是一个数据结构, 每个神经元有2个可调参数, 输入经过了参数的计算得到输出, `y = wx + b`.
多个电子神经进行一定形式的连接就形成了神经网络(neural network).

### 多层感知机MLP

一个NN的基础实现是多层感知机(multilayer perceptron), 就是多个神经元作为输入, 然后连到下一层, 经过了多层的神经网络, 最后连接到一个神经元上作为输出.

我把他联系到"因果论", 每个事情的发生都是由他的原因决定的, 而这个原因大多是非常多个因素一起决定的.
那么多个因素像丝线连接到了这个事件, 像是"业", 而每个因素的权重是不同的.
比如我今天吃不吃早饭, 要看是不是周末, 天下不下雨, 冰箱有没有存货, 昨晚有没有吃夜宵等因素.
这些因素的权重是不同的, 每天早上"是否周末, 是否下雨, 冰箱有没有存货, 昨晚有没有吃夜宵"都是有确定值的, 所以我今天吃不吃早饭其实是确定的.
而我脑内其实确实有这些因素的"权重", 但我自己不能明确知道, 而通过机器学习, 把参数训练出来, 就可以准确估计我吃不吃早饭了.
(认真思考的朋友应该发现了, 实际因素是更多的, 所以参数越多, 训练成功以后的预测就会越准确)

训练的过程大概是以下这样的, 其中会有一些通用的概念:
+ 以初始参数和训练数据运行一下网络加权求和, 得到一个结果.
+ 把这个结果和"期望结果"对比, 用来对比当前结果和期望结果的函数叫做**损失函数**, 就是 loss 函数, 得出的 loss 值表示与期望结果的偏差.
+ 通过**优化函数**调整参数, 因为参数是巨大的, 调整参数是有一些固定的成熟方法的. 顺利的情况下, 再次运行网络后的 loss 值应该是不断下降的.

我们可以感受到, **损失函数是由训练目标决定的**, 比如训练目标是图片, 损失函数就是对比像素的. 而**优化函数是和网络连接方式**有关的.
我们可以看到训练结果其实就是调整参数, 所以**训练结果的模型文件中大部分都是参数**. 我们的输入经过了带着这些参数的网络运行, 就得到了"预测的结果"作为模型输出.

### 优化架构

而仔细思考的朋友可能感受到了, 真实场景中会有很多不同的业务, 这些业务中需要调整参数结构才能更接近业务:

+ 在输入是图片的情况下, 图片的比较小的区域其实可以共用一个参数, 因为他们是图片的一个特征.
  有一种方案产生了: 依次把原图的3*3的格子算加权和, 合成一个像素. 这样可以共用一个参数, 总参数就大大减少.
  这样的网络叫卷积神经网络(convolutional neural network), 加权的策略叫做卷积核, 就是卷积计算f(g(x))里的g(x).
+ 对于 CNN 需要连接比较远的像素的关系, 又不像降低像素分辨率, 有了 UNet 这样跳跃连接的方案, UNet 是对 CNN 的优化.
+ transformer 建立了输入 token 之间的互相关系, 动态计算权重, 在输入的顺序是重要的情况下比 mlp 更有意义, 缺点是每个 token 都要两两交互, 复杂度变成了O(n²).

因为他们都是基于 NN 的, 所以训练的时候相同点是运行的时候进行加权求和, 通过损失函数判断效果, 优化函数调整参数, 迭代训练, 训练交付的是参数.
在 stable diffusion 里使用的 vae 和 clip 也是基于 NN 的模型.

### LLM和DM

llm 是基于 transformer 的, dm 一开始是基于 unet 的, 而后也改用 transformer 来训练以获得更好的训练效果.
他们都是在 transormer 这种结构之上的应用层.

### 多模态与agent

多模态模型的范围其实特别大, 能处理多个模态的都叫多模态, 其实输出类型是这个模型的主要功能.
比如语言图片的多模态, 如果输出是语言的模型, 只是在输入层增加了图片识别的工具, 输出还是语言, 主要模型是 llm, 作用可能是看设计图生成代码.
而输出是图片的模型, 如果是以语言为输入, 比如 seedream, 其实主模型是 dm, 只是在输入的使用用 llm 把语言转换为 latent 和 clip, 这个模式其实和 comfyui 的 agent 或者是自己用桌面 agent 控制 comfyui 有点像.

另外, 工具调用相关的 tool, mcp, cli 都是 agent 负责调用的, agent 的作用就是协调工作流, 运营上下文, 在调用 llm api 和业务之间周旋的软件.

### 基于transformer的模型的特点

神经网络真的很有意思, 因为**制造他的人也不知道他会有什么功能, 也不知道如何控制他**.
因为他是**自组织**的系统, 在大规模的情况下**涌现**了"智能".

transformer 让大家觉得 ai 变得史无前例的聪明, 因为自注意机制, 输入模型的语言更能影响输出.
这种架构会不会产生意识, 我认为不会, 因为**现在他的技术上的能力已经超过大多数人很多了, 但意识还没有出现, 而大多数人是有意识的**.
说明我们脑子的架构比 transformer 更复杂, 架构不同, 再大数据量的训练也弥补不了的.

今年年初的赛博果蝇以复制结构来尝试制造智能, 不需要训练, 结果非常成功, 不知道是不是另一条智能之路.
但也有一种可能, 训练的结果参数是保存在蛋白质折叠方式里, 制造赛博果蝇的时候其实把模型已经一起带着了.

人类的神经网络的硬件和软件都那么复杂, 到底可不可能是符合进化论演化来的, 还是有上帝制造的, 那是另外一个值得想的问题了.
